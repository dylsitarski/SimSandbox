## What works

- Cargo workspace with nine crates: `simsandbox-core`, `simsandbox-expr`, `simsandbox-eq`, `simsandbox-agents`, `simsandbox-file`, `simsandbox-cli`, `simsandbox-views`, `simsandbox-session`, `simsandbox-app`, plus the Python package in `python/` (its own workspace); CI on Windows, macOS and Linux.
- Block contract: required `Block` trait plus optional `Equations`, `Rollback`, `Derivatives`, `Realtime` capability traits (`crates/simsandbox-core/src/block.rs`).
- SI units (`units.rs`) with prefixes, common non-SI and US/imperial units ([ADR 0047](decisions/0047-unit-vocabulary.md)); a connection needs the same unit at both ends, and `units.convert` blocks convert between scales of one quantity ([ADR 0045](decisions/0045-units-in-typed-equations.md)).
- Model graph with unit-, shape- and direction-checked signal connections (`graph.rs`).
- Co-simulation master: fixed communication step, Jacobi exchange; direct feedthrough (outputs declare the inputs they depend on, `PortSpec::depends_on`) evaluated in dependency order at every communication point and inside fused groups at every evaluation, algebraic loops found when the model is built, named in a notice and solved by Newton's method (or fixed-point iteration, or refused: `run.loops`, ADR 0040, `loops.rs`); kernel-owned state, including tables (populations of rows with stable ids that grow and shrink, ADR 0034); variable-length population ports; a model seed (`run.seed`) with counter-based random numbers per Block and step (`random.rs`); snapshots and rewind that also restore parameter values, tables and the step count; live parameter changes; `Simulator::restart` re-initialises from current parameters (`sim.rs`). `ParamSpec::initial_condition` marks parameters that only apply on restart.
- Parameter access: `Model::param`, `Model::params`, `Model::block_ids`, `Simulator::model`, `Simulator::param`; `set_param` accepts any finite value and rejects unknown names (`SimError::UnknownParam`) and NaN or infinite values (`SimError::InvalidParam`); `ParamSpec` ranges are suggestions ([ADR 0011](decisions/0011-parameter-entry.md)).
- Equation domain: Euler, RK4, Dormand–Prince 5(4), each with speed/accuracy labels; fusion of equation Blocks into one system (`crates/simsandbox-eq`).
- Typed equations ([ADR 0017](decisions/0017-typed-equations.md)), with `input u, F` lines for input ports (quantities using them feed through, ADR 0040): `simsandbox-expr` parses and evaluates expressions with column-accurate errors; `eq.equations` blocks (`EquationSet`) turn lines like `dx/dt = sigma*(y - x)` and `E = …` into states, computed outputs, parameters (default 1) and initial values `x0`; discrete maps `x[n+1] = …` (method `iterate`) and formula-only blocks (method `evaluate`), [ADR 0021](decisions/0021-maps-formulas-and-sweeps.md); stored in model files as `equations`; units in brackets (`input F [N]`, `param m [kg] = 1000`, `state v [m/s] = 0`, `dv/dt = … [m/s^2]`, [ADR 0049](decisions/0049-state-declarations-and-rate-units.md)) make every line checked for balance, values computed in SI ([ADR 0045](decisions/0045-units-in-typed-equations.md)); verified against the built-in Lorenz (bit for bit), exponential decay, the Lotka–Volterra invariant and the exact logistic map at r = 4.
- Sweeps ([ADR 0027](decisions/0027-explicit-experiments.md), [ADR 0028](decisions/0028-sweeps-as-samples.md)): a model with no states is evaluated at the samples of the file's top-level `sample` section (default: a grid over its first parameter): designs `grid`, `list`, `random`, `latin_hypercube` and `sobol` (`crates/simsandbox-core/src/sampling.rs`), any number of parameters, at most 250 000 samples, invalid values are load errors; each sample recorded with the swept parameters as signals; a grid over two parameters also offers every signal as a grid `grid.<signal>` placed by the parameters; recomputed on every slider change; the sweep bar (design, count, seed, parameters with range and points, "+ parameter" and ×) replaces Run/Pause in the app and resets the views when what can be shown changes; unordered samples are drawn as markers; old `controls.sweep` is read leniently and converted.
- Example systems: Lorenz, coupled oscillator, damped pendulum (`eq.pendulum`), heat along a rod (`eq.heat_rod`, temperature and position at 50 points as grid outputs, rod length a parameter) and orbiting test particles (`eq.orbits`, a 200-point set), each verified against known solutions; example files `examples/lorenz.ssbx.json`, `examples/coupled-oscillators.ssbx.json`, `examples/predator-prey.ssbx.json` (typed equations), `examples/logistic-map.ssbx.json` (a map), `examples/resonance.ssbx.json` (formulas, swept), `examples/resonance-map.ssbx.json` (a grid over two parameters), `examples/resonance-samples.ssbx.json` (a Sobol sweep), `examples/pendulum.ssbx.json`, `examples/heat-rod.ssbx.json` and `examples/orbits.ssbx.json` `examples/grazing.ssbx.json` (grass as an ODE, sheep as agents) `examples/cruise-control.ssbx.json` (a PI controller with feedthrough, fused with the car; units checked) and `examples/units.ssbx.json` (a shaker in mm drives springs in m through a conversion block).
- Port shapes: scalar, vector, grid (`Shape::Grid { nx, ny }`) and point set (`Shape::Points { count, dim }`).
- Model files ([ADR 0007](decisions/0007-json-model-files.md), [ADR 0012](decisions/0012-controls-in-model-files.md), [ADR 0023](decisions/0023-automatic-fusion.md)): automatic fusion of connected equation blocks with identical methods, `fusion: off`, explicit `groups`; block-type registry (`crates/simsandbox-core/src/registry.rs`), equation types `eq.lorenz` and `eq.coupled_oscillator` (`simsandbox_eq::register`), JSON load/save with errors located by line/column or path, lenient `controls`, a `run` section with `dt` and optional `t_end` ([ADR 0013](decisions/0013-run-section.md)), JSON Schema (`crates/simsandbox-file/model.schema.json`).

## Known limitations

- Population ports cannot have direct feedthrough, and code-built `EquationGroup`s refuse members with it ([ADR 0040](decisions/0040-feedthrough-and-algebraic-loops.md)). Loops are solved with a finite-difference Jacobian each time, which costs one pass per loop value per Newton iteration.
- Physical (acausal) ports are not implemented.
- The master uses a fixed step with no coupling-error estimate, iteration or rollback.
- `FusedSystem::rhs` and the master's fused-group right-hand side allocate per call; fine for small models, revisit before real-time use with large groups.
- Inside a fused group, inputs from blocks outside the group are held over each step (no extrapolation yet, ADR 0023). Changing the fusion switch in the app rebuilds the model and restarts the run.
- Filters are evaluated per sample; filters over a window of history (FFT, smoothing, sections) are not built. Cuts are edited as numbers in the Data window, not drawn on a heat map; free-line cuts are plotted against the fraction along the line only (distance needs field units). Removing a filter leaves views bound to its outputs empty until they are rebound.
- Views beyond `plot.xy`, `plot.3d`, `plot.heatmap`, `plot.profile`, `plot.scatter`, `plot.surface`, `plot.contour` and `eq.pendulum` are not built; surfaces are drawn on the CPU (at most 40 000 quads, depth-sorted, no tick marks, only the axis ranges), and contours are lines without labels or filled bands; contours of unordered samples (triangulated) are not built; heat maps place cells only along evenly spaced lines (2D grids are numbered by cell); derived signals cannot use grids or point sets; `plot.scatter` shows only the newest frame, without trails. Tiles are laid out in an automatic grid; they cannot be resized or reordered. The colour-blind-safe palette is fixed; viewer theme settings are not built ([ADR 0015](decisions/0015-pluggable-views.md)).
- The 3D view projects on the CPU and draws with the egui painter, at most 20 000 points per frame; it suits trajectories, not meshes or fields, which need wgpu paint callbacks ([ADR 0008](decisions/0008-native-egui-ui.md)).
- Sweeps recompute every sample on each applied change, in the background. Models with states cannot be sampled yet (reductions, [ADR 0027](decisions/0027-explicit-experiments.md)). A `list` design cannot be edited in the app, and grids over three or more parameters offer no grid views. `t` in an expression filter is the sample number in a sweep.
- On Linux the file dialogs need the XDG desktop portal (standard on GNOME and KDE desktops); without it Open and Save as do nothing, and drag and drop or a command-line path still work.
- The grazing field's grid is fixed at 40 × 40 (its size is one model parameter since 2026-10-23). Heat maps do not keep equal scales on both axes, so a square field can look stretched. Grazers move by a random walk only (no searching for grass).
- Subsystems ([ADR 0043](decisions/0043-subsystems.md)): no libraries or import from another file, no ungrouping; sweeps cannot vary declared parameters and filters cannot use them; renaming a block inside a subsystem renames flat names in controls by pattern; agent update orders of blocks inside subsystems are set in the file, not the side panel.
- Node canvas ([ADR 0042](decisions/0042-node-canvas.md), [ADR 0050](decisions/0050-data-layer-and-canvas-undo.md)): no copy and paste; undo covers canvas edits only; filters and views are on the model level only, and only expression filters reading scalar model-level outputs can be promoted to blocks; a wire between mismatched units or shapes is refused only when the edit is applied (the draft banner says why). While a draft is pending, side-panel parameter changes apply to the running model, not the draft. A block with a `start` entry ignores its initial-condition parameters, and the side panel does not show this yet.
- Populations are left out of `simsandbox run`'s CSV (rows cannot hold a varying number of values); `--format json` and the Python API include them. Blocks with tables cannot join fused groups.
- Headless rendering draws the views as they stand after the run, one sample per pixel, without the app's controls (the 3D views still print their mouse hint); filters and view selections saved in the file apply. Python and `render` take a whole model file; there is no Python call to step a running model, set parameters between steps or rewind. The Python package is built from source, not published.
- A step in progress cannot be interrupted: commands, Pause included, wait for it; the toolbar shows how long it has run but not yet which block ([ADR 0035](decisions/0035-simulation-worker-thread.md)). One model is open at a time. Headless screenshots wait a fixed wall time (`--after`), not for a number of samples.
- Plotted series and rewind history are thinned (every other point dropped) beyond 100 000 points and 10 000 snapshots, so very long runs lose resolution in the past.
- A model built in code cannot be saved (Blocks do not know their type name); files are the source for saving.
- Only models with no states can be swept; sweeping models with states (bifurcation diagrams) is a later feature. Maps have no step-number variable `n` yet.
- Typed equations without units are dimensionless and unchecked; formulas feeding a block that gives no units are not checked ([ADR 0046](decisions/0046-units-of-declared-parameters.md)). There are no symbolic Jacobians yet ([ADR 0017](decisions/0017-typed-equations.md)). Applying edited equations restarts the run from t = 0.
- Integer method options are written as numbers with a decimal point (`"substeps": 4.0`).
