## What works

- Cargo workspace with nine crates: `simsandbox-core`, `simsandbox-expr`, `simsandbox-eq`, `simsandbox-agents`, `simsandbox-file`, `simsandbox-cli`, `simsandbox-views`, `simsandbox-session`, `simsandbox-app`, plus the Python package in `python/` (its own workspace); CI on Windows, macOS and Linux.
- Block contract: required `Block` trait plus optional `Equations`, `Rollback`, `Derivatives`, `Realtime` capability traits (`crates/simsandbox-core/src/block.rs`).
- SI units (`units.rs`) with prefixes, common non-SI and US/imperial units ([ADR 0047](decisions/0047-unit-vocabulary.md)); a connection needs the same unit at both ends, and `units.convert` blocks convert between scales of one quantity ([ADR 0045](decisions/0045-units-in-typed-equations.md)).
- Model graph with unit-, shape- and direction-checked signal connections (`graph.rs`).
- Co-simulation master: fixed communication step, or several clocks in one model, each stepping its blocks at its own step or listed instants in exact ticks ([ADR 0066](decisions/0066-models-nest-as-blocks.md), [ADR 0067](decisions/0067-experiments-and-time-from-data.md)); Jacobi exchange; direct feedthrough (outputs declare the inputs they depend on, `PortSpec::depends_on`) evaluated in dependency order at every communication point and inside fused groups at every evaluation, algebraic loops found when the model is built, named in a notice and solved by Newton's method (or fixed-point iteration, or refused: `run.loops`, ADR 0040, `loops.rs`); kernel-owned state, including tables (populations of rows with stable ids that grow and shrink, ADR 0034); variable-length population ports; a model seed (`run.seed`) with counter-based random numbers per Block and step (`random.rs`); snapshots and rewind that also restore parameter values, tables and the step count; live parameter changes; `Simulator::restart` re-initialises from current parameters (`sim.rs`). `ParamSpec::initial_condition` marks parameters that only apply on restart.
- Parameter access: `Model::param`, `Model::params`, `Model::block_ids`, `Simulator::model`, `Simulator::param`; `set_param` accepts any finite value and rejects unknown names (`SimError::UnknownParam`) and NaN or infinite values (`SimError::InvalidParam`); `ParamSpec` ranges are suggestions ([ADR 0011](decisions/0011-parameter-entry.md)).
- Equation domain: explicit Euler, RK4 and Dormand–Prince 5(4), and the implicit backward Euler and TR-BDF2 for stiff systems ([ADR 0057](decisions/0057-phase-2-plan.md) item 2), each with speed/accuracy labels; fusion of equation Blocks into one system, stateless blocks included ([ADR 0051](decisions/0051-stateless-blocks-join-fused-groups.md)) (`crates/simsandbox-eq`).
- Typed equations ([ADR 0017](decisions/0017-typed-equations.md)), with `input u, F` lines for input ports (quantities using them feed through, ADR 0040): `simsandbox-expr` parses and evaluates expressions with column-accurate errors; `eq.equations` blocks (`EquationSet`) turn lines like `dx/dt = sigma*(y - x)` and `E = …` into states, computed outputs, parameters (default 1) and initial values `x0`; discrete maps `x[n+1] = …` (method `iterate`) and formula-only blocks (method `evaluate`), [ADR 0021](decisions/0021-maps-formulas-and-sweeps.md); stored in model files as `equations`; units in brackets (`input F [N]`, `param m [kg] = 1000`, `state v [m/s] = 0`, `dv/dt = … [m/s^2]`, [ADR 0049](decisions/0049-state-declarations-and-rate-units.md)) make every line checked for balance, values computed in SI ([ADR 0045](decisions/0045-units-in-typed-equations.md)); verified against the built-in Lorenz (bit for bit), exponential decay, the Lotka–Volterra invariant and the exact logistic map at r = 4. Arrays on grids ([ADR 0060](decisions/0060-arrays-in-typed-equations.md)): `grid x [m] = 0 .. L, 50` and quantities with a value per cell, neighbours by `prev`/`next` along an axis, array parameters `param m[k] = …` ([ADR 0069](decisions/0069-repetition-in-blocks.md)), index axes `grid k = n` with `at`, `argmaxof`, `argminof` and reductions over cells; comparisons `<`, `<=`, `>`, `>=` in every expression ([ADR 0070](decisions/0070-studies-are-blocks.md)).
- Studies ([ADR 0070](decisions/0070-studies-are-blocks.md), [ADR 0071](decisions/0071-sweeps-are-studies.md)): the only way to run a model at many points is a study block over a model (a definition or a file): designs `grid`, `list`, `random`, `latin_hypercube`, `sobol` and `file` (`crates/simsandbox-core/src/sampling.rs`), any number of parameters, at most 250 000 points, replicates and seeds, `reduce` formulas; results as lines of cells, or 2D grids for a grid over two parameters; recomputed when the study's inputs change; "Study this model" on a used model or on the whole model. A file's top-level `sample` is refused; old `controls.sweep` is dropped with a warning; a model with no states is not swept but runs in time.
- Built-in block types: `eq.equations` (typed equations), `eq.lorenz`, `eq.coupled_oscillator`, `eq.pendulum`, `eq.heat_rod` (temperature and position at 50 points as grid outputs), `eq.orbits` (a 200-point set) and `eq.grass`, each verified against known solutions; `agents.grazers` (a population, ADR 0034); `input.value`, `input.pointer` and `input.file` (recorded data, [ADR 0048](decisions/0048-units-of-external-data.md)); `units.convert`; `study` (ADR 0070). `simsandbox describe` lists them with their methods and settings.
- 20 examples in `examples/`, each current, free of warnings and run by a test (`every_example_is_current_and_runs`): a forced spring (one spring model used twice, its force set in one use and driven by a wire in the other), Lorenz, coupled oscillators, predator–prey (typed equations), cruise control (a PI controller with feedthrough, fused with the car, units checked), steering the car with keys, tuning the controller's gain (a study of a model defined in the file, its arrays read by a formula), units (a shaker in mm drives springs in m), the Platoon (a model defined once, used three times), the logistic map, the resonance curve, map and samples (studies of a spring model over one parameter, a grid of two and a Sobol design), the pendulum and dragging its bob, heat along a rod (a built-in block and typed arrays), Gray–Scott spots (reaction–diffusion on a 2D grid), orbiting particles and sheep grazing (grass as an ODE, sheep as agents).
- Port shapes: scalar, vector, grid (`Shape::Grid { nx, ny }`), point set (`Shape::Points { count, dim }`) and population (`Shape::Population { dim }`, a varying number of points).
- Model files ([ADR 0007](decisions/0007-json-model-files.md), [ADR 0012](decisions/0012-controls-in-model-files.md), [ADR 0023](decisions/0023-automatic-fusion.md)): automatic fusion of connected equation blocks with identical methods, `fusion: off`, explicit `groups`; block-type registry (`crates/simsandbox-core/src/registry.rs`), JSON load/save with errors located by line/column or path, lenient `controls`, a `run` section with `dt` and optional `t_end` ([ADR 0013](decisions/0013-run-section.md)), JSON Schema (`crates/simsandbox-file/model.schema.json`).
- Desktop app `simsandbox-app` ([ADR 0008](decisions/0008-native-egui-ui.md)): opens a model file (native Open dialog, drag and drop, command-line argument) or a built-in example; starts running at once; "New model…" and "Edit equations…" open an equation editor whose Apply runs the equations, keeping parameter values that still exist; run/pause, Restart (re-initialise from current parameters), rewind slider that branches (with a recorder, [ADR 0064](decisions/0064-recorder-node.md)), pause at the file's `t_end` or the end of its data; docked panes ([ADR 0053](decisions/0053-docked-panes-inspector-and-node-values.md)): Views, Diagram, an Inspector listing every parameter by path with a typed field, units, initial-condition markers, search and formulas, and Controls holding the pinned values with optional sliders ([ADR 0054](decisions/0054-controls-pane-pins-and-node-toggles.md), [ADR 0011](decisions/0011-parameter-entry.md)), any pane in its own tab or window; Save (back to the opened file) and Save as (native dialog, asks before overwriting), with Ctrl+O, Ctrl+S and Ctrl+Shift+S; saving writes parameters, step, sliders, speed and view ([ADR 0012](decisions/0012-controls-in-model-files.md), [ADR 0013](decisions/0013-run-section.md)); the simulation runs on its own thread ([ADR 0035](decisions/0035-simulation-worker-thread.md), `crates/simsandbox-app/src/live.rs`): the window sends commands (the newest of a kind wins), reads a shared history to draw and never waits on a step, and shows how long a slow step has been running; a model's studies run on the worker, never on the window's thread, with their progress shown and given up for newer changes ([ADR 0071](decisions/0071-sweeps-are-studies.md)); speed control and editable step with wall-clock pacing in 8 ms ticks with a 7 ms budget and an achieved-speed warning ([ADR 0010](decisions/0010-live-loop-pacing.md)); sliders apply while dragged for real-time models and on release otherwise, the parameter's field showing the pending value in the warning colour ([ADR 0037](decisions/0037-when-parameter-changes-apply.md)); speed and accuracy labels; pluggable views ([ADR 0015](decisions/0015-pluggable-views.md), `crates/simsandbox-views`) of the outputs (grids and point sets recorded whole as fields; what is recorded, wiring decides since ADR 0063): `plot.xy` (any signals against time or each other, [ADR 0018](decisions/0018-one-xy-plot.md); lines of cells such as a study's results against each other cell by cell), `plot.3d` (rotatable, zoomable), `plot.heatmap` (a field over two axes, each `t` or a declared coordinate such as `rod.position` or a study's parameter, with a swap button and uneven coordinates drawn correctly; optional log colour scale; [ADR 0024](decisions/0024-heat-map-axes-and-coordinates.md)), settings shown only where they apply ([ADR 0025](decisions/0025-index-aware-view-settings.md)), `plot.profile` (line fields now against their coordinate), `plot.values` (newest values as numbers with units; lines of cells as a table), `plot.surface` (a grid field as a rotatable 3D surface over the heat map's axes, coloured and shaded, optional log scale) and `plot.contour` (lines of equal value by marching squares, `levels` and log spacing), both also for a line of cells over time, filters ([ADR 0030](decisions/0030-filters-and-native-visualization.md)–[0032](decisions/0032-filters-as-a-graph.md)) edited in a "Data…" window: expressions (derived signals, which may use each other) and cuts through 2D grids along x, along y or free lines ([ADR 0031](decisions/0031-cut-filters.md)), saved in `controls.filters` and `plot.scatter` (a point set); infinite and NaN values leave gaps instead of crashing the plot, plus the domain view `eq.pendulum`, offered only for models with a pendulum (`applies_to`, registered by `simsandbox-eq` behind its `views` feature), shown together as tiles: the model's own views first, more from the presets under "More views…" (plot against time, phase portrait, 3D trajectory) ([ADR 0016](decisions/0016-model-curated-views.md)), each with slot pickers and a close button; a colour slot (fading by `t` by default, or colour by any signal) and a `trail_length` style property in each tile's style menu (seconds of trail; 0 shows none, -1 the whole run; against time it is a scrolling window); the scroll wheel zooms 2D plots around the pointer; derived signals are expression filters; the tiles are read from and saved to `controls.views` (the older `controls.view` is still read); the examples list curated views (Lorenz: 3D and time series; oscillators: time series and phase portrait); a log tile left of the rewind bar (the newest notice, warning or error on one line, dimmed after 8 s; "Log" opens every message, newest first) and a one-line model description with the full text on hover; `--view time|phase|3d|diagram`, `--window signals|equations` and `--screenshot` for headless checks.
- CLI ([headless guide](guides/headless.md)): `simsandbox run FILE` writes every output as CSV or, with `--format json`, JSON including populations, using the file's `run` section unless `--dt`/`--t-end` override it, or for a model whose only runs are its studies one row per run; it replays run files, applies `--inputs`, and writes probes (`--probe`, `--save-probes`); `describe [TYPE]` (every block, view and filter type, and the units, as JSON), `schema [run]`, `check FILE` (JSON report with paths, exit status 1 on failure), `render FILE --out IMAGE.png` (the model's views, or with `--diagram` its block diagram, drawn without a window), `start-from FILE --t S` and `upgrade FILE`; `simsandbox lorenz` with `--method euler|rk4|dopri5`.
- Model files: unsaved changes are asked about before they are lost; older forms convert on reading and are reported; `simsandbox upgrade` writes the current form ([ADR 0044](decisions/0044-unsaved-changes-and-older-files.md)).
- Declared parameters ([ADR 0043](decisions/0043-subsystems.md), [ADR 0046](decisions/0046-units-of-declared-parameters.md), [ADR 0056](decisions/0056-formulas-and-parameters-in-the-app.md)): a model's own parameters, with units, which block parameters use in formulas.
- Models that use models ([ADR 0066](decisions/0066-models-nest-as-blocks.md), [ADR 0068](decisions/0068-one-kind-of-nested-model.md)): a block entry uses a model file (`file`) or a model defined in the file (`models`, used by `model`), on the user's clock or its own (`clock`: a step or listed times); a used model's inputs are its input blocks and it offers declared `outputs`; across clocks, models exchange values through probe links into input blocks; `files` replaces files deep inside one use; models on new data are evaluated when a link delivers; the app runs them as one model on several clocks, with rewind and run files; editing a used model asks whether to change the original, a new copy with its own file, or a local copy; "Make model" from a selection and moving a definition to its own file and back.
- Time from data ([ADR 0067](decisions/0067-experiments-and-time-from-data.md)): a model with no states that reads recorded data steps at the data's own sample times and ends at the last.
- Probes ([ADR 0062](decisions/0062-probes-recording-and-replay.md), [ADR 0063](decisions/0063-probes-on-wires.md)): nodes on wires that record what they are wired to, when they are told to (every step, every n steps or seconds, at listed times), keep a set amount, feed views and filters, write CSV and NumPy files (as they record, or when asked), and feed blocks; the implicit history records only what views and filters read. The recorder ([ADR 0064](decisions/0064-recorder-node.md)) keeps snapshots for rewind within a memory budget.
- Node canvas ([ADR 0042](decisions/0042-node-canvas.md), [ADR 0050](decisions/0050-data-layer-and-canvas-undo.md), [ADR 0052](decisions/0052-canvas-for-every-node-place.md)): the app's Diagram tab shows blocks with typed ports and wires (backward wires routed underneath) and edits them with the mouse; a data layer with probes, filters, views and the recorder as nodes; undo and redo; used models as nodes, opened to see and edit their inside or expanded in place; "Make model", Duplicate, "Study this model" (on a used model or the whole model), exposing ports and parameters with a click inside a model ([ADR 0074](decisions/0074-model-interfaces.md)), wires that drive values ([ADR 0075](decisions/0075-parameters-are-inputs-with-defaults.md)) and promoting a filter to a block; edits rebuild and restart, or wait as a draft with the reason; node values shown on open nodes ([ADR 0055](decisions/0055-open-nodes-subsystem-values-deferred-windows.md)); "Start from here" and "Forget start state" in the toolbar; `--view diagram` opens on it.
- Python package `simsandbox` (`python/`, [ADR 0041](decisions/0041-headless-interface.md)): `describe`, `check`, `schema`, `upgrade`, `examples`; `Model` (the file as a dict) with `add_block`, `connect`, `set`, `declare`, `add_model`, `define`, `link`, `add_probe`, `group`, `duplicate`, `study`, `as_study`, `promote`, `schedule`, `set_run` and `save`; `run` (numpy arrays in `Results`, populations as lists of arrays; `Composed` for models that use models), `run_probes` (`ProbeRun`), `start_from` and `render` (views or the diagram, as PNG); `Run` for run files.
- Inputs ([ADR 0058](decisions/0058-inputs-live-scheduled-replayed.md)) and run files ([ADR 0059](decisions/0059-run-files.md)): `input.value` and `input.pointer` blocks; keys and views (`plot.xy`, the pendulum view) bound in `controls.inputs`; every change during a run recorded at step boundaries and replayed after a rewind ("Replaying input"); `run.inputs` as the model's default schedule; Runs menu (Save run…, replay a saved run, use a run as the model's schedule); `simsandbox run RUN.run.json`, `--inputs`, `check` and `schema run`; Python `Run`, `Model.run(inputs=...)`, `Model.schedule`. Examples "Drag the bob" and "Steer the car with keys".
- 489 tests in the workspace plus 26 Python tests, including verification against analytic solutions and convergence order.

## Known limitations

- Population ports cannot have direct feedthrough, and code-built `EquationGroup`s refuse members with it ([ADR 0040](decisions/0040-feedthrough-and-algebraic-loops.md)). Loops are solved with a finite-difference Jacobian each time, which costs one pass per loop value per Newton iteration.
- Physical (acausal) ports are not implemented.
- One model uses several cores only for array phases of at least 2^20 cell operations (about 512 × 512 cells on this 4-core machine), and only cell-by-cell work: integrators' vector updates run on one core below 2^20 state values, Dormand–Prince's at any size (sums over 2^20 cells or more use several, ADR 0077) ([performance](design/performance.md)).
- The master uses a fixed step with no coupling-error estimate, iteration or rollback.
- `FusedSystem::rhs` and the master's fused-group right-hand side allocate per call; fine for small models, revisit before real-time use with large groups.
- Inside a fused group, inputs from blocks outside the group are held over each step (no extrapolation yet, ADR 0023). Changing the fusion switch in the app rebuilds the model and restarts the run.
- Filters are evaluated per sample; filters over a window of history (FFT, smoothing, sections) are not built. Cuts are edited as numbers in the Data window, not drawn on a heat map; free-line cuts are plotted against the fraction along the line only (distance needs field units). Removing a filter leaves views bound to its outputs empty until they are rebound.
- Views beyond `plot.xy`, `plot.3d`, `plot.heatmap`, `plot.profile`, `plot.scatter`, `plot.surface`, `plot.contour`, `plot.values` and `eq.pendulum` are not built; units print in SI form (`kg/s` for N·s/m, `1/s` for rad/s), not as the equations write them; surfaces are drawn on the CPU (at most 40 000 quads, depth-sorted, no tick marks, only the axis ranges), and contours are lines without labels or filled bands; contours of scattered points (a study's unordered designs, which would need triangulating) are not built; derived signals cannot use grids or point sets; `plot.scatter` shows only the newest frame, without trails. Tiles are laid out in an automatic grid; they cannot be resized or reordered. The colour-blind-safe palette is fixed; viewer theme settings are not built ([ADR 0015](decisions/0015-pluggable-views.md)).
- The 3D view projects on the CPU and draws with the egui painter, at most 20 000 points per frame; it suits trajectories, not meshes or fields, which need wgpu paint callbacks ([ADR 0008](decisions/0008-native-egui-ui.md)).
- Studies ([ADR 0070](decisions/0070-studies-are-blocks.md), [ADR 0071](decisions/0071-sweeps-are-studies.md)): the Inspector's form cannot edit a `list` design's points (they are edited as JSON); a formula reading a study's results declares the number of runs itself (`grid k = n`); a study runs all its points again whenever any input changes (points already run are not reused); grids over three or more parameters give lines indexed by run, not grids; a study keeps one value, or a vector at given times or data samples (`at_times`, `at_samples`), per run, not whole series (`keep: "series"` is refused, [Q52](open-questions.md)); a vector result over a grid of two parameters is refused (three axes, until [ADR 0081](decisions/0081-shapes-are-lists-of-axes.md)). In the app a study runs within the step that needs it: one run by a change at t = 0 (which restarts the model) is not given up and holds the worker, not the window, until it ends; diagram edits are checked without running studies, so an error inside a study's runs shows only when the worker runs it; progress is shown in runs, without an estimate of time left.
- On Linux the file dialogs need the XDG desktop portal (standard on GNOME and KDE desktops); without it Open and Save as do nothing, and drag and drop or a command-line path still work.
- The grazing field's grid is fixed at 40 × 40 (its size is one model parameter since 2026-10-23). Heat maps do not keep equal scales on both axes, so a square field can look stretched. Grazers move by a random walk only (no searching for grass).
- Named axes ([ADR 0080](decisions/0080-named-axes.md)): a declared or defined quantity has at most two axes (ports and views take one or two); vectors per run are not built yet; `solve` copies its matrix at each evaluation (dense, for small systems).
- Driven parameters ([ADR 0075](decisions/0075-parameters-are-inputs-with-defaults.md)): built 2026-11-05, checked by tests, headless renders and a screenshot under Xvfb, not yet by the owner in the window; a parameter of a model on its own clock cannot be driven; a used model's parameter read in a formula other than itself cannot be driven; a whole array parameter cannot be driven from one vector signal (its elements can, one by one).
- Exposing ([ADR 0074](decisions/0074-model-interfaces.md)): a wire from outside to an inner port that is not exposed is refused (expose it with a click first); wires across an outline reach a model expanded directly in the one drawn, not one nested deeper; a use's own inputs inside a model cannot be exposed by a click.
- Models defined in the file ([ADR 0068](decisions/0068-one-kind-of-nested-model.md)): no ungrouping (a definition's blocks cannot be put back in place of its use); filters cannot use declared parameters.
- Node canvas ([ADR 0042](decisions/0042-node-canvas.md), [ADR 0050](decisions/0050-data-layer-and-canvas-undo.md)): no copy and paste (Duplicate copies within a model); undo covers canvas edits only; filters and views are on the model level only, and only expression filters reading scalar model-level outputs can be promoted to blocks; a wire between mismatched units or shapes is refused only when the edit is applied (the draft banner says why). While a draft is pending, side-panel parameter changes apply to the running model, not the draft. A block with a `start` entry ignores its initial-condition parameters, and the side panel does not show this yet.
- Populations are left out of `simsandbox run`'s CSV (rows cannot hold a varying number of values); `--format json` and the Python API include them. Blocks with tables cannot join fused groups.
- Headless rendering draws the views as they stand after the run, one sample per pixel, without the app's controls (the 3D views still print their mouse hint); filters and view selections saved in the file apply. Python and `render` take a whole model file; there is no Python call to step a running model, set parameters between steps or rewind. The Python package is built from source, not published.
- A step in progress cannot be interrupted, except to give up a study it runs ([ADR 0071](decisions/0071-sweeps-are-studies.md)): other commands, Pause included, wait for it; the toolbar shows how long it has run but not yet which block ([ADR 0035](decisions/0035-simulation-worker-thread.md)). One model is open at a time. Headless screenshots wait a fixed wall time (`--after`), not for a number of samples.
- Probes ([ADR 0063](decisions/0063-probes-on-wires.md)): a signal wired to a view during a run has no past until Restart (recompute on demand comes later, on request); a probe feeds blocks of its own model, and a used model only through its input blocks ([ADR 0066](decisions/0066-models-nest-as-blocks.md)); probes cannot feed other probes nor record filters with clocks of their own; field views (heat map, profile, surface) read one recording. A model loaded headless without saved views records everything.
- Rewind needs a recorder ([ADR 0064](decisions/0064-recorder-node.md)); one per model, for the whole model and the models it uses (a used model's own recorder is not used).
- Plotted series and rewind history are thinned (every other point dropped) beyond 100 000 points, and snapshots beyond 10 000 or the recorder's memory budget (256 MB by default), so very long runs lose resolution in the past.
- A model built in code cannot be saved (Blocks do not know their type name); files are the source for saving.
- Maps cannot use the step number `n` in their equations yet, only in indices such as `x[n+1]`.
- Typed equations without units are dimensionless and unchecked; formulas feeding a block that gives no units are not checked ([ADR 0046](decisions/0046-units-of-declared-parameters.md)). There are no symbolic Jacobians yet ([ADR 0017](decisions/0017-typed-equations.md)). Applying edited equations restarts the run from t = 0.
- Integer method options are written as numbers with a decimal point (`"substeps": 4.0`).
- Inputs ([ADR 0058](decisions/0058-inputs-live-scheduled-replayed.md)): no `input.gamepad` yet; only `plot.xy` and the pendulum view send the pointer, and the pendulum view only for `eq.pendulum` models; keys drive `input.value` blocks only (two keys each). Input faster than one step is not seen. The rewind slider does not yet show where recorded input lies. Opening a saved run puts its seed, step and schedule into the open model, so Save would write them (the log says so when they differ). The Runs menu does not mark stale runs; opening one warns in the log.
- Models that use model files ([ADR 0066](decisions/0066-models-nest-as-blocks.md); all six steps done, the last 2026-11-05):
  - A value given by formula to a model on its own clock is taken once, when the model is built. Values that change during a run reach such a model through a probe link.
  - `run --dt` is refused for them (each model keeps its own step). With inputs, probes or a run file they run as one model on several clocks, so `--model` does not apply then.
  - In the app a model on new data is evaluated at every instant (values agree with the headless runner at deliveries unless its formulas read `t`); Save As to another folder does not rebase the files the model names.
  - Open nodes inside used models are not saved by path. A model defined in a file that no use or study names is read but not built, so a problem inside it shows once it is used.
