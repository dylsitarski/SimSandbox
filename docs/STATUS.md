**Phase:** 1 · Composition ([roadmap](roadmap.md#phase-1--composition), order and scope in [ADR 0033](decisions/0033-phase-1-plan.md)). **Gate:** an ODE model and an agent model run in one graph (the grazing model). Phase 0's gate (Lorenz live on the desktop with sliders) was met 2026-10-16 and confirmed by the owner on Windows and Linux on 2026-10-19.

## What works

- Cargo workspace with seven crates: `simsandbox-core`, `simsandbox-expr`, `simsandbox-eq`, `simsandbox-file`, `simsandbox-cli`, `simsandbox-views`, `simsandbox-app`; CI on Windows, macOS and Linux.
- Block contract: required `Block` trait plus optional `Equations`, `Rollback`, `Derivatives`, `Realtime` capability traits (`crates/simsandbox-core/src/block.rs`).
- SI units with dimension checking and automatic conversion at connect time (`units.rs`).
- Model graph with unit-, shape- and direction-checked signal connections (`graph.rs`).
- Co-simulation master: fixed communication step, Jacobi exchange; kernel-owned state; snapshots and rewind that also restore parameter values; live parameter changes; `Simulator::restart` re-initialises from current parameters (`sim.rs`). `ParamSpec::initial_condition` marks parameters that only apply on restart.
- Parameter access: `Model::param`, `Model::params`, `Model::block_ids`, `Simulator::model`, `Simulator::param`; `set_param` accepts any finite value and rejects unknown names (`SimError::UnknownParam`) and NaN or infinite values (`SimError::InvalidParam`); `ParamSpec` ranges are suggestions ([ADR 0011](decisions/0011-parameter-entry.md)).
- Equation domain: Euler, RK4, Dormand–Prince 5(4), each with speed/accuracy labels; fusion of equation Blocks into one system (`crates/simsandbox-eq`).
- Typed equations ([ADR 0017](decisions/0017-typed-equations.md)): `simsandbox-expr` parses and evaluates expressions with column-accurate errors; `eq.equations` blocks (`EquationSet`) turn lines like `dx/dt = sigma*(y - x)` and `E = …` into states, computed outputs, parameters (default 1) and initial values `x0`; discrete maps `x[n+1] = …` (method `iterate`) and formula-only blocks (method `evaluate`), [ADR 0021](decisions/0021-maps-formulas-and-sweeps.md); stored in model files as `equations`; verified against the built-in Lorenz (bit for bit), exponential decay, the Lotka–Volterra invariant and the exact logistic map at r = 4.
- Sweeps ([ADR 0027](decisions/0027-explicit-experiments.md), [ADR 0028](decisions/0028-sweeps-as-samples.md)): a model with no states is evaluated at the samples of the file's top-level `sample` section (default: a grid over its first parameter): designs `grid`, `list`, `random`, `latin_hypercube` and `sobol` (`crates/simsandbox-core/src/sampling.rs`), any number of parameters, at most 250 000 samples, invalid values are load errors; each sample recorded with the swept parameters as signals; a grid over two parameters also offers every signal as a grid `grid.<signal>` placed by the parameters; recomputed on every slider change; the sweep bar (design, count, seed, parameters with range and points, "+ parameter" and ×) replaces Run/Pause in the app and resets the views when what can be shown changes; unordered samples are drawn as markers; old `controls.sweep` is read leniently and converted.
- Example systems: Lorenz, coupled oscillator, damped pendulum (`eq.pendulum`), heat along a rod (`eq.heat_rod`, temperature and position at 50 points as grid outputs, rod length a parameter) and orbiting test particles (`eq.orbits`, a 200-point set), each verified against known solutions; example files `examples/lorenz.ssbx.json`, `examples/coupled-oscillators.ssbx.json`, `examples/predator-prey.ssbx.json` (typed equations), `examples/logistic-map.ssbx.json` (a map), `examples/resonance.ssbx.json` (formulas, swept), `examples/resonance-map.ssbx.json` (a grid over two parameters), `examples/resonance-samples.ssbx.json` (a Sobol sweep), `examples/pendulum.ssbx.json`, `examples/heat-rod.ssbx.json` and `examples/orbits.ssbx.json`.
- Port shapes: scalar, vector, grid (`Shape::Grid { nx, ny }`) and point set (`Shape::Points { count, dim }`).
- Model files ([ADR 0007](decisions/0007-json-model-files.md), [ADR 0012](decisions/0012-controls-in-model-files.md), [ADR 0023](decisions/0023-automatic-fusion.md)): automatic fusion of connected equation blocks with identical methods, `fusion: off`, explicit `groups`; block-type registry (`crates/simsandbox-core/src/registry.rs`), equation types `eq.lorenz` and `eq.coupled_oscillator` (`simsandbox_eq::register`), JSON load/save with errors located by line/column or path, lenient `controls`, a `run` section with `dt` and optional `t_end` ([ADR 0013](decisions/0013-run-section.md)), JSON Schema (`crates/simsandbox-file/model.schema.json`).
- Desktop app `simsandbox-app` ([ADR 0008](decisions/0008-native-egui-ui.md)): opens a model file (native Open dialog, drag and drop, command-line argument) or a built-in example; starts running at once; "New model…" and "Edit equations…" open an equation editor whose Apply runs the equations, keeping parameter values that still exist; run/pause, Restart (re-initialise from current parameters), rewind slider that branches, pause at the file's `t_end`; parameter panel with a typed field per parameter, units, initial-condition markers and opt-in sliders with editable ranges ([ADR 0011](decisions/0011-parameter-entry.md)); Save (back to the opened file) and Save as (native dialog, asks before overwriting), with Ctrl+O, Ctrl+S and Ctrl+Shift+S; saving writes parameters, step, sliders, speed and view ([ADR 0012](decisions/0012-controls-in-model-files.md), [ADR 0013](decisions/0013-run-section.md)); speed control and editable step with wall-clock pacing, an 8 ms per-frame budget and an achieved-speed warning ([ADR 0010](decisions/0010-live-loop-pacing.md)); speed and accuracy labels; pluggable views ([ADR 0015](decisions/0015-pluggable-views.md), `crates/simsandbox-views`) of the file's `controls.plots` (all outputs if none; grids and point sets are recorded whole as fields): `plot.xy` (any signals against time or each other, [ADR 0018](decisions/0018-one-xy-plot.md)), `plot.3d` (rotatable, zoomable), `plot.heatmap` (a field over two axes, each `t` or a declared coordinate such as `rod.position` or a swept parameter, with a swap button and uneven coordinates drawn correctly; optional log colour scale; [ADR 0024](decisions/0024-heat-map-axes-and-coordinates.md)), settings shown only where they apply ([ADR 0025](decisions/0025-index-aware-view-settings.md)), `plot.profile` (line fields now against their coordinate), `plot.surface` (a grid field as a rotatable 3D surface over the heat map's axes, coloured and shaded, optional log scale) and `plot.contour` (lines of equal value by marching squares, `levels` and log spacing), both also for a line of cells over time, filters ([ADR 0030](decisions/0030-filters-and-native-visualization.md)–[0032](decisions/0032-filters-as-a-graph.md)) edited in a "Data…" window: expressions (derived signals, which may use each other) and cuts through 2D grids along x, along y or free lines ([ADR 0031](decisions/0031-cut-filters.md)), saved in `controls.filters` and `plot.scatter` (a point set); infinite and NaN values leave gaps instead of crashing the plot, plus the domain view `eq.pendulum`, offered only for models with a pendulum (`applies_to`, registered by `simsandbox-eq` behind its `views` feature), shown together as tiles: the model's own views first, more from the presets under "More views…" (plot against time, phase portrait, 3D trajectory) ([ADR 0016](decisions/0016-model-curated-views.md)), each with slot pickers and a close button; a colour slot (fading by `t` by default, or colour by any signal) and a `trail_length` style property for the selected tile under "View" in the parameter panel (seconds of trail; 0 shows none, -1 the whole run; against time it is a scrolling window); the scroll wheel zooms 2D plots around the pointer; derived signals are expression filters; the tiles are read from and saved to `controls.views` (the older `controls.view` is still read); the examples list curated views (Lorenz: 3D and time series; oscillators: time series and phase portrait); a log tile left of the rewind bar (the newest notice, warning or error on one line, dimmed after 8 s; "Log" opens every message, newest first) and a one-line model description with the full text on hover; `--view time|phase|3d`, `--window signals|equations` and `--screenshot` for headless checks.
- CLI: `simsandbox run FILE` writes every output as CSV, using the file's `run` section unless `--dt`/`--t-end` override it, or for a model without states one row per sample (sample number, swept parameters, outputs); `simsandbox lorenz` with `--method euler|rk4|dopri5`.
- 142 tests, including verification against analytic solutions and convergence order.

## Known limitations

- Fused equation groups require outputs that depend only on state and parameters (no direct feedthrough), so algebraic loops are not supported ([ADR 0002](decisions/0002-layered-block-contract.md)).
- Physical (acausal) ports are not implemented.
- The master uses a fixed step with no coupling-error estimate, iteration or rollback.
- `FusedSystem::rhs` and the master's fused-group right-hand side allocate per call; fine for small models, revisit before real-time use with large groups.
- Inside a fused group, inputs from blocks outside the group are held over each step (no extrapolation yet, ADR 0023). Changing the fusion switch in the app rebuilds the model and restarts the run.
- Filters are evaluated per sample; filters over a window of history (FFT, smoothing, sections) are not built. Cuts are edited as numbers in the Data window, not drawn on a heat map; free-line cuts are plotted against the fraction along the line only (distance needs field units). Removing a filter leaves views bound to its outputs empty until they are rebound.
- Views beyond `plot.xy`, `plot.3d`, `plot.heatmap`, `plot.profile`, `plot.scatter`, `plot.surface`, `plot.contour` and `eq.pendulum` are not built; surfaces are drawn on the CPU (at most 40 000 quads, depth-sorted, no tick marks, only the axis ranges), and contours are lines without labels or filled bands; contours of unordered samples (triangulated) are not built; heat maps place cells only along evenly spaced lines (2D grids are numbered by cell); derived signals cannot use grids or point sets; `plot.scatter` shows only the newest frame, without trails. Tiles are laid out in an automatic grid; they cannot be resized or reordered. The colour-blind-safe palette is fixed; viewer theme settings are not built ([ADR 0015](decisions/0015-pluggable-views.md)).
- The 3D view projects on the CPU and draws with the egui painter, at most 20 000 points per frame; it suits trajectories, not meshes or fields, which need wgpu paint callbacks ([ADR 0008](decisions/0008-native-egui-ui.md)).
- Sweeps run on the UI thread and recompute every sample on each slider change; large designs (up to 250 000 samples) make sliders sluggish. Models with states cannot be sampled yet (reductions, [ADR 0027](decisions/0027-explicit-experiments.md)). A `list` design cannot be edited in the app, and grids over three or more parameters offer no grid views. `t` in an expression filter is the sample number in a sweep.
- The app does not track unsaved changes: opening another model or closing the window discards them without asking.
- On Linux the file dialogs need the XDG desktop portal (standard on GNOME and KDE desktops); without it Open and Save as do nothing, and drag and drop or a command-line path still work.
- The simulation runs on the UI thread ([ADR 0010](decisions/0010-live-loop-pacing.md)); a heavy model slows the window's controls as well as the plot.
- Plotted series and rewind history are thinned (every other point dropped) beyond 100 000 points and 10 000 snapshots, so very long runs lose resolution in the past.
- A model built in code cannot be saved (Blocks do not know their type name); files are the source for saving.
- Only models with no states can be swept; sweeping models with states (bifurcation diagrams) is a later feature. Maps have no step-number variable `n` yet.
- Typed equations are dimensionless and have no inputs, so typed blocks cannot be wired to other blocks yet; there are no symbolic Jacobians yet ([ADR 0017](decisions/0017-typed-equations.md)). Applying edited equations restarts the run from t = 0.
- Integer method options are written as numbers with a decimal point (`"substeps": 4.0`).
