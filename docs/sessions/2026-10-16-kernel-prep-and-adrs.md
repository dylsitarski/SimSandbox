## Notes for the next session

- Pop-out stall (owner, Linux): reproduced only as a slowdown under Xvfb (frame rate fell by about two thirds with a tab popped out; the main window kept drawing). `--screenshot` never finishes while a tab is popped out (the screenshot event does not come back), so pop-out cannot be checked that way. If vsync off does not fix Wayland, try deferred viewports ([Q33](../open-questions.md)).
- egui's default fonts lack `→` (U+2192): it draws as a box. Use "to" or `->` in anything the app shows.
- Cut filters use `at` for their cut positions inside the flattened filter entry, so filter and view places are `canvas`. A promoted block between two fused blocks separates them, so results change slightly unless fusion is off.
- A bare `0` is dimensionless, so `dx/dt = 0 [m]` is refused; write the rate as a parameter with a unit. Consider letting a literal zero take any dimension if this proves tedious.
- `cargo test --workspace` stops at the first failing test binary; use `--no-fail-fast` to see every failure at once.
- With units, `sin(t)` is an error because `t` is in seconds; the units example uses `param f [Hz]` and `sin(2*pi*f*t)`. Several app and diagram tests had wired `cruise.e` (m/s) into `car.F` (N); they now use `cruise.F`.
- Feedthrough (`loops.rs`): `OutputPlan` nodes are feedthrough output ports; edges follow routes into the inputs they depend on; Tarjan components give the order (sources first) and the loops. `solve` evaluates a unit's whole `compute_outputs`/`Equations::outputs` and copies only the port being finalised, so ports of one Block can be ordered separately. Loop tolerance is relative 10⁻¹⁰, not machine precision. A group's right-hand side cannot return errors, so a failed loop fills `dx` with NaN and the error is returned after the step.
- Grazing: the sheep eat from the grass they saw at the start of the step and report a grazing rate (fraction of a cell's grass eaten per second), which the grass applies over the next step; the books balance up to that one-step lag (test `grass_eaten_matches_energy_gained_to_first_order_in_the_step`). Competition for a cell happens only within a step, through `Update::share`. The example settles near G* = metabolism / (efficiency × c) = 0.4 kg/m² and about 380 sheep.
- Populations: at t0 a Block's population inputs are empty, as fixed inputs are zero, because every Block computes its first outputs before the first exchange. A Block's random stream is `random::stream(model seed, Block name)`; draw with `Draws::new(ctx.seed, ctx.step, id)` (and `u64::MAX` as the step in `init_tables`), so rewind replays draws with nothing saved. Rows are oldest first; `Table::retain` keeps order.
- The window must not hold the history's read guard (`Live::history`) while calling `Live::call`: the worker may need the write lock for the command (a rebuild), and the window would wait on it. Appends never block: `Session::push` uses `try_write` and keeps samples pending; `flush(true)` before the worker idles. A history replaced by `rebuild_history` keeps its `Arc`, so the window's handle stays valid. `Live::call` replies after the model and status are republished, so tests can read them straight after.
- Sweeps: `Session::resample` starts a `ResampleJob`; with `load_deferred` (the app) the worker continues it with `resume_resample(budget)` each tick, restoring the panel's parameter values after every slice; `Session::load` (tests) finishes at once.
- Filters run per recorded sample: `Session::record` computes source frames, then `sample_cuts`, and pushes all; `set_filters` replays the recorded sources (scalar outputs and source fields) through new filters. A cut whose input is not a base field (a `grid.` field of a two-parameter grid sweep) is whole: `resample` computes it once after all samples (`whole_cut`, `cut_frames(.., true)`). Expression slots are `t`, outputs, expression filters in dependency order, then parameters; failed expressions are dropped and the rest recompiled so slots stay consistent.
- Slot pickers show field names (`cuts1.x`), not labels; legends and axes show labels (`spring.w`).
- View selections are JSON (`ViewEntry::selection`, `View::selection`/`set_selection`/`edit_selection`); the views crate depends on serde for them. A selection that does not parse drops the view with a warning, like other bad controls.
- Heat map axes: `heat_axes` resolves `x`/`y` to time or a grid axis; unbound axes take the directions left in order. `axis_map` maps texels to cells, one per cell when even, resampled at the smallest spacing (≤ 1024 texels) when not. A coordinate that is not strictly monotonic falls back to cell numbers at draw time (the picker and load check prevent binding non-coordinates).
- Sweeps (ADR 0028): `simsandbox_file::Sampling::plan` makes the points (`simsandbox_core::sampling`), `ModelFile::sampling` gives the effective sampling (the default for a stateless model without `sample`), and `Session::resample` evaluates them: scalars are outputs, expression filters, then the swept keys; history index `sample`, never thinned (`keep_all`). Grid points vary the first parameter fastest, so `grid.<signal>` frames are the sample columns as they are (cell (i, j) at j·nx + i). `Sweep::unordered` is false only for a one-parameter grid. Old `controls.sweep` conversion runs after the profile-selection conversion so converted cuts get the `grid.` prefix. Sobol uses Joe–Kuo direction numbers for up to 10 parameters, starting at the zero point; the stratification tests check one point per slice and the (0, m, 2)-net property.
- Surfaces use the painter's algorithm (quads sorted by projected centre depth), which can misorder quads on folds seen edge-on; fine for height fields, revisit with wgpu depth buffering. `plot.3d` keeps a fit valid at every rotation (its box stays still while turning); the surface fits its current rotation to fill short tiles (`Frame::begin(.., steady)`).
- A linear colour scale hides everything but the resonance peak (amplitude ~ 1/c); the example uses `log_colour`.
- Fusion was built in the master rather than as ADR 0023's consequences sketched (the loader building an `EquationGroup` and renaming ports): members stay separate Blocks and only their stepping changes, so names, ids, snapshots and `set_param` needed no mapping. The master's group right-hand side is bit-identical to `FusedSystem`'s (test `master_fusion_matches_the_fused_system_bit_for_bit`).
- With fusion the oscillator energy plot autoscaled to rounding noise (10⁻¹⁴), which looked like drift; plots now keep a minimum span of 10⁻⁶ of the largest magnitude (owner's request).
- egui panics in debug builds when asked to draw a NaN or infinite point ("Comparing NaN vectors"); `crates/simsandbox-views/tests/render.rs` renders every built-in view headlessly with such values. New views should be added to it.
- The coupled-oscillator energy drift was measured with `simsandbox run` at dt = 0.01, 0.005, 0.0025: +11.5 %, +4.9 %, +2.3 % at t = 100, first order in dt, matching a coupling delay of dt/2 acting as negative damping on the antisymmetric mode (Q16).
